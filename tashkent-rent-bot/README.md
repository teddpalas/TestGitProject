# Telegram-бот для поиска квартиры в Ташкенте

Личный помощник для долгосрочной аренды: читает новые объявления из `@Apartament_999`, проверяет условия и отправляет подходящие варианты в личный чат с ботом. Полные совпадения приходят сразу с обычным звуковым уведомлением; близкие варианты и объявления с небольшим количеством недостающих данных — без звука.

Код написан на Python 3.11+. Для чтения канала используется пользовательская сессия Telethon, для доставки — Telegram Bot API. Одного токена бота недостаточно для чтения произвольного чужого канала.

## Правила отбора

| Условие | Полное совпадение | Допуск для тихой отправки |
|---|---|---|
| Дом | Новостройка, введена в эксплуатацию не более трёх лет назад | Без послаблений |
| Прежнее проживание | Никто не жил | Ранее уже жили |
| Комнаты | От двух | Без послаблений |
| Общая площадь | От 40 м² включительно | Без послаблений |
| Аренда | Не более $800 в месяц | Более $800, но не более $850 |
| Путь до офиса | Не более 20 минут пешком | Более 20, но не более 25 минут |

Одновременно допускается **не больше одного отклонения**: цена, маршрут или прежнее проживание. Например, квартира за $850, где уже жили, отклоняется. Коммунальные платежи, комиссия и залог не входят в порог месячной аренды.

Для тихой отправки также подходят объявления с одним-двумя неизвестными критериями, если все остальные известные параметры строго совпадают. Неуказанный срок аренды тоже считается неизвестным. Объявления с большим количеством пробелов, посуточная аренда и продажа отбрасываются.

Парсер работает по текстовым признакам. Он не угадывает дату сдачи дома по слову «новостройка», не считает свежий ремонт доказательством первого проживания и не извлекает сведения из фотографий. OCR и внешняя языковая модель не используются. Если указан только год ввода дома, пограничный возраст не считается подтверждённым. «Евродвушка» без ясной планировки не подтверждает две комнаты.

**Практическое ограничение:** короткие объявления без даты сдачи дома, истории проживания или точного адреса могут не пройти фильтр. До настройки на реальных публикациях полнота распознавания не гарантируется.

## Когда приходят сообщения

Всё расписание задано в `Asia/Tashkent`:

- Полное совпадение — сразу, в том числе ночью и в выходные.
- Тихие объявления в понедельник–пятницу до 16:50 — в очередь до 16:50 того же дня.
- Тихие объявления в будни начиная с 16:50 — сразу.
- Тихие объявления в субботу и воскресенье — сразу.

Праздники отдельно не учитываются. «Сразу» означает после обнаружения и обработки публикации: при стандартной настройке канал опрашивается каждые 20 секунд; сетевые сбои и ограничения API могут увеличить задержку.

Оригиналы пересылаются без звука; для полного совпадения бот добавляет одну сводку со звуковым уведомлением. Если Bot API не может переслать публикацию или канал защитил содержимое, бот отправляет сводку со ссылкой. Защита канала не обходится. Бот не управляет громкостью телефона и не отключает режим «Не беспокоить» — включите уведомления в его чате и выберите нужную мелодию в Telegram.

## Установка

Код находится в каталоге `tashkent-rent-bot` репозитория [teddpalas/TestGitProject](https://github.com/teddpalas/TestGitProject/tree/main/tashkent-rent-bot). Скачайте репозиторий и откройте терминал в этом каталоге.

Рекомендуется отдельное виртуальное окружение. В Windows:

```text
python -m venv .venv
.venv\Scripts\python -m pip install -e .
```

В командах ниже `python` обозначает Python из этого окружения: в Windows можно использовать `.venv\Scripts\python`, в Linux/macOS — `.venv/bin/python`.

Зависимости также перечислены в `requirements.txt`. Проект не содержит Docker, JavaScript или сценариев оболочки.

## Подключение Telegram

1. Получите `api_id` и `api_hash` для приложения на [my.telegram.org](https://my.telegram.org/apps).
2. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните его токен локально.
3. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_BOT_TOKEN`.
4. Выполните `python -m rentbot login`. Введите телефон, код Telegram и пароль двухэтапной проверки, если он установлен, в локальном терминале.
5. Выполните `python -m rentbot whoami` и укажите полученный положительный числовой ID в `TELEGRAM_CHAT_ID`.
6. Откройте своего бота в Telegram и нажмите **Start / Запустить**. Проверьте, что пользовательский аккаунт видит исходный канал; для устойчивого получения публикаций подпишитесь на него.

Сессия пользовательского аккаунта сохраняется в `DATA_DIR`. `.env`, сессии, база и локальный справочник адресов исключены из Git. Не публикуйте их и не пересылайте коды входа. При публикации проекта через веб-интерфейс загружайте только исходники и файлы-примеры: `.gitignore` не защищает от ручной загрузки секретов.

## Адрес офиса и пешие маршруты

Укажите `OFFICE_LAT` и `OFFICE_LON` в локальном `.env`, самостоятельно проверьте точку входа в офис на карте, затем установите `OFFICE_LOCATION_CONFIRMED=true`. Личная рабочая точка не включена в исходники.

В новом `.env.example` выбран **Geoapify**: `ROUTING_PROVIDER=geoapify`. Зарегистрируйтесь в [Geoapify My Projects](https://myprojects.geoapify.com/), создайте проект и скопируйте его ключ из раздела **API Keys** в локальную строку `GEOAPIFY_API_KEY=`. Используется только пешеходный режим `walk`. Карточки содержат атрибуцию Geoapify и OpenStreetMap. Ключ передаётся сервису по HTTPS; полный URL запроса с ключом не записывается в журнал.

Альтернативный провайдер — openrouteservice: установите `ROUTING_PROVIDER=ors` и заполните `ORS_API_KEY` ключом из [личного кабинета HeiGIT](https://account.heigit.org/). Используется пешеходный профиль `foot-walking` по адресу `https://api.heigit.org/openrouteservice/v2/directions/foot-walking/json`. Для совместимости старый `.env` без `ROUTING_PROVIDER` продолжает выбирать ORS. Автоматического переключения между сервисами нет; ключи не взаимозаменяемы.

Выбранный сервис получает координаты начала и конца маршрута. Оценка по прямой линии не подменяет время пути. Без подтверждённых координат, при отсутствии маршрута или недоступности сервиса время считается неизвестным, а не нулевым. Кэш разделён по провайдерам. Для Geoapify проверяется геометрия маршрута: если начало или конец оказались дальше 100 м от заданных точек, такой маршрут не считается подтверждённым.

Точная точка квартиры может быть указана в объявлении либо задана в локальном справочнике:

1. Скопируйте `locations.example.json` в `locations.json`.
2. Для каждого проверенного корпуса укажите точный адрес/уникальные названия в `aliases`, координаты, дату ввода дома в `commissioned_on` и источник подтверждения в `source`.
3. Установите `confirmed: true` только после проверки. Пример намеренно имеет `confirmed: false`.

Не используйте широкие названия районов, метро или всего большого ЖК как адрес конкретного дома. Совпадения ищутся по границам алиасов; неоднозначное расположение нельзя выдавать за точный адрес. История проживания в справочнике не хранится — она относится к конкретной квартире.

## Проверка и запуск

```text
python -m rentbot check-config
python -m rentbot demo
python -m rentbot inspect sample_listing.txt
python -m rentbot run
```

`demo` показывает работу правил на встроенных примерах без Telegram. `inspect` разбирает локальный UTF-8 текст объявления без сетевого расчёта маршрута. `check-config` проверяет настройки; он не доказывает, что Telegram и маршрутизатор доступны. `run` запускает наблюдение, обработку команд и отправку.

В личном чате под строкой ввода доступны четыре кнопки: **📊 Состояние**, **📋 Правила**, **⏸ Пауза**, **▶️ Возобновить**. Пауза останавливает только отправку: чтение канала и сохранение очереди продолжаются. Возобновление сохраняет обычное расписание тихих сообщений. Ответы на кнопки приходят без звука.

Клавиатура появляется после `/start`, `/menu` и вместе с ответами бота. Если она скрыта, отправьте `/menu`. Текстовые команды тоже работают:

- `/menu` — показать кнопки управления;
- `/status` — состояние и очередь;
- `/pause` — приостановить доставку;
- `/resume` — возобновить доставку;
- `/rules` — показать правила.

Кнопки и команды доступны только владельцу, указанному в `TELEGRAM_CHAT_ID`. Групповые чаты не предназначены для управления этим ботом.

Для непрерывных уведомлений процесс должен постоянно работать на включённом компьютере или сервере с интернетом. После закрытия терминала, выключения компьютера или перехода в сон наблюдение не продолжается само по себе. Автозапуск и размещение на сервере в этот проект не включены.

## Настройки и сохранность очереди

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `SOURCE_CHANNEL` | `Apartament_999` | Публичный исходный канал |
| `DATA_DIR` | `data` | SQLite и пользовательская сессия |
| `POLL_SECONDS` | `20` | Интервал опроса канала |
| `EDIT_SCAN_LIMIT` | `100` | Число последних сообщений для проверки изменений |
| `BACKFILL_LIMIT` | `0` | Сколько старых сообщений обработать при самом первом запуске |
| `LOCATIONS_FILE` | `locations.json` | Локальный справочник проверенных адресов |
| `ROUTING_PROVIDER` | `geoapify` в примере; `ors`, если переменной нет | Выбранный сервис пеших маршрутов |
| `GEOAPIFY_API_KEY` | Пусто | Личный ключ Geoapify, только в локальном `.env` |

При первом запуске старые объявления не рассылаются, если `BACKFILL_LIMIT=0`. После перезапуска приложение продолжает с сохранённой позиции. Очередь и журнал отправок хранятся в SQLite. Проверяются правки последних сообщений и актуальность объявления перед отправкой; бесконечная история правок не сканируется.

Неизменённые повторы подавляются; распознавание одной квартиры в разных публикациях работает по доступным признакам и не гарантирует обнаружение всех дублей. Новая версия объявления может заменить ожидающую в очереди. Когда ранее тихий вариант впервые становится полным совпадением, он отправляется сразу со звуком. После первой громкой отправки повторные уведомления для того же ключа подавляются.

Доставка имеет семантику *at-least-once*: редкий сбой после принятия сообщения Telegram, но до записи результата в SQLite, может привести к повторной отправке. Повторяемые ошибки сохраняют сообщение в очереди для следующей попытки.

```text

```

Тесты используют локальные примеры и подмены внешних сервисов. Они не требуют личных токенов. Работа с реальным аккаунтом Telegram, выбранным каналом и ключом маршрутизатора проверяется отдельно после настройки доступа.
