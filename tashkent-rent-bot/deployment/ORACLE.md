# Размещение на Oracle Cloud Always Free

Эта инструкция и файлы подготавливают развёртывание. Их наличие не означает,
что сервер уже создан или бот уже перенесён.

## Бесплатная виртуальная машина

Используйте домашний регион аккаунта и официальный образ Ubuntu 24.04 LTS.
Стартовая конфигурация: VM.Standard.A1.Flex, 1 OCPU, 2 GB RAM, загрузочный диск
50 GB со стандартной производительностью Balanced. Для A1 нужен полный образ
Ubuntu ARM. Альтернатива — VM.Standard.E2.1.Micro с Ubuntu x86 и 1 GB RAM.
Перед созданием проверьте метку Always Free и свободные квоты своего аккаунта.
Пробные кредиты не подтверждают, что выбранный ресурс останется бесплатным.

Достаточно публичной подсети, Internet Gateway и публичного IP. SSH-порт 22
откройте только для своего адреса /32. Публичный веб-сайт, порты 80/443 на вход,
балансировщик и NAT Gateway боту не нужны. Не включайте платные дополнения.

Oracle может изъять малоиспользуемую Always Free VM; свободные мощности могут
отсутствовать. Автоперезапуск внутри VM не восстанавливает изъятый сервер.
Сохраняйте отдельную копию данных и ключа SSH.

## Установка без запуска

Скопируйте исходники проекта в `/opt/tashkent-rent-bot`. Для загрузки исходников
можно использовать публичный GitHub; секреты и каталог `data` туда не входят.
На сервере выполните:

```text
sudo python3 /opt/tashkent-rent-bot/deployment/install.py --install
```

Установщик создаёт пользователя `rentbot`, виртуальное окружение и службу
systemd с автозапуском. Он не запускает службу до переноса данных.
Конфигурация хранится в `/etc/tashkent-rent-bot/.env`, данные — в
`/var/lib/tashkent-rent-bot`. Настройки DATA_DIR и LOCATIONS_FILE в службе
принудительно указывают на этот постоянный каталог.

## Перенос данных

1. Сначала проверьте SSH-доступ, установку зависимостей и доступ сервера к
   Telegram и Geoapify. До этого локальный бот может продолжать работать.
2. Остановите локальный процесс и убедитесь, что он завершился.
3. Из каталога локального проекта выполните через его Python:

   ```text
   python deployment/export_state.py --output data/oci/private-state.tar.gz
   ```

   Экспорт требует свободной блокировки бота и делает согласованные резервные
   копии SQLite вместе с данными WAL. Архив содержит `.env`, Telegram-сессию,
   очередь, историю отправок и справочник адресов, если он существует.
4. Передайте архив напрямую по SSH/SCP. Это приватные данные: не помещайте его
   в GitHub, публичную ссылку или журнал. Распакуйте в отдельный закрытый каталог.
5. Установите `.env` в `/etc/tashkent-rent-bot/.env` с владельцем root:root и
   правами 0600. Файлы `data/*` установите в `/var/lib/tashkent-rent-bot` с
   владельцем rentbot:rentbot и правами 0600; каталог должен иметь права 0700.
   Сохраните TELEGRAM_CHAT_ID из действующей конфигурации: аккаунт для чтения
   канала и аккаунт-получатель могут различаться.
6. Проверьте настройки и запустите единственный экземпляр:

   ```text
   sudo python3 /opt/tashkent-rent-bot/deployment/install.py --check
   sudo systemctl start tashkent-rent-bot
   sudo systemctl status tashkent-rent-bot --no-pager
   ```

7. Проверьте реальный пеший маршрут, обновление `last_poll` в базе и ответ
   на кнопку «Состояние» в правильном Telegram-чате. После перезапуска службы
   курсор чтения, очередь и история должны сохраниться. Локальный процесс
   оставьте выключенным. При откате сначала остановите облачную службу.
